# 自动签到（auto-checkin）

抓取课堂直播画面里的签到二维码 → 解码 → 自动提交，抢在 3 秒一变的码失效前完成签到。

按周课表在每节课的监视窗口内自动工作（课前 + 课间各一次），平时只是个几十 MB 的后台进程，进窗口才开浏览器。

> ## ⚠️ 请先读这一段
>
> 这个工具会**代替你完成课堂签到**。使用和传播它都可能违反你所在学校的教学管理规定，后果由使用者自负。
>
> - 本项目仅供**个人学习与技术研究**（浏览器自动化、图像识别、本地服务、打包分发）。
> - 作者不鼓励、也不为任何违反校规或学术诚信的用法负责。
> - 你的账号密码只保存在本机 `data\credentials.json`，本工具不会上传到任何地方；但**请自行保管这个文件**，不要提交进 Git 仓库、不要发给别人。
> - 如果学校明确禁止此类工具，请停止使用。

## 一、安装

双击 `auto-checkin-setup-*.exe`（安装包），一路下一步即可：

- 默认装在 `%LOCALAPPDATA%\Programs\AutoCheckin`，**不需要管理员权限**
- 可以勾选「开机自启」
- 桌面会生成「自动签到控制台」快捷方式

> 如果没有安装包，也可以直接用便携版：解压 `auto-checkin-portable.zip`，双击其中的 `auto-checkin.exe` 不行——**要用 `打开控制台.lnk`**（原因见下）。

**⚠️ 不要直接双击 `auto-checkin.exe`**：它是无控制台程序，双击不会弹任何窗口（只是打印帮助然后退出），看起来像"没反应"。

## 二、首次配置（四步）

打开控制台后，如果顶部提示「还没配置完」，按下面顺序做：

### ① 填学校账号

「设置」页 → 「学校账号（jAccount）」→ 填学号和密码 → 点「保存账号」。

密码只存在本机 `data\credentials.json`，接口不回显、不外传。

### ② 发现课程

「全部课程」页 → 右上「重新发现」→ 等约 40 秒（会开浏览器自动登录 Canvas）。

完成后「课程库」里会出现你这学期所有带直播的课程。

### ③ 把课加到课表

在同一页的「添加到课表」里：

| 字段 | 填法 |
|---|---|
| 课程 | 从下拉里选（来自课程库） |
| 星期 | 周一 ~ 周日 |
| 节次 | 如 `1,2`（第 1、2 课时） |
| 周次 | 如 `1-16`、`2,4,6`、`1-8,10-16` |
| 教室 | 可选 |
| 签到地点 | 可选，留空表示用「设置」页的全局地点 |

点「添加」，列表里就会多一段。

### ④ 启动监控

- 控制台里点「启动」（或双击 `run-autowatch.cmd`）
- 想开机自动跑：双击 `start-watchdog.cmd` 一次，它会在后台看护（每 5 分钟检查一次）

## 三、日常使用

| 我想… | 怎么做 |
|---|---|
| 看现在状态 | 双击 `status-autowatch.cmd`，或打开控制台 |
| 打开控制台 | 双击 `打开控制台.lnk` |
| 暂停某节课的自动签到 | 控制台「本周课表」取消勾选（**不会删除**，随时能勾回来） |
| 彻底删掉某节课 | 「全部课程」页行尾垃圾桶（需要确认） |
| 临时停止监控 | 双击 `stop-autowatch.cmd` |
| 停止控制台后端 | 关掉控制台窗口，或双击 `stop-dashboard.cmd` |

控制台是本地网页（`127.0.0.1:8791`），带随机 token，只在本机可访问。

## 四、它会告诉你"为什么没签上"

每节课结束后，**这一节的结果就挂在课表对应的那一行上**：

```
高等代数I
周二 第 3-4 课时 · 下院212 · 监视 10-27 09:55 → 11:50      已签到
✓ 09:59 签到成功

工程物理与化学基础（1）
周四 第 3-4 课时 · 上院315 · 监视 10-29 09:55 → 11:50      没签上
✗ 09:50 盯了 5386 轮，画面里一直没出现签到码
```

同时**屏幕右下角会弹一张小卡片**（成功绿点、失败红点，7 秒自动消失），不用一直盯着控制台。

可能的原因：没登录 / 网络问题 / 直播页没打开 / 没有屏幕流 / 有码但提交失败 / 一直没出现码。

**「一直没出现码」通常不是程序坏了**——有些课几周才点一次名。

## 五、常见问题

**Q：控制台页面显示"缺少访问令牌"或"拒绝连接"？**
关掉窗口，重新双击 `打开控制台.lnk`（或 `run-dashboard.cmd`）即可。

**Q：改了代码但控制台没变化？**
控制台后端是独立进程，**不热加载**：关掉窗口重开，或双击 `stop-dashboard.cmd` 再打开。

**Q：改完监控设置什么时候生效？**
要重启监控进程（`stop-autowatch.cmd` → `run-autowatch.cmd`）。

**Q：装了新版本后数据还在吗？**
在。数据在 `%APPDATA%\auto-checkin\`，重装程序不会动它。

**Q：控制台顶部提示「连着的后端是旧版本」？**
说明窗口连上的是旧进程（常见于装完新版本、旧后端还没退）。关掉窗口，重新双击 `打开控制台.lnk` 就好。

**Q：怎么知道某一节到底签没签上？**
看课表那一行：绿标「已签到」+ `✓ 09:59 签到成功` 就是签上了；红标「没签上」会附原因。想二次确认可以双击 `check-records.cmd` 查服务器记录。

**Q：能同时跑两个吗？**
不能。监控进程有单实例保护，第二个会直接提示"已经在运行"。

## 六、隐私与风险

- 账号密码只存本机 `data\credentials.json`，不上传任何地方
- 签到请求里带的位置信息（经纬度 + 地址文字）是**由程序自己报的**，服务端只按收到的参数记录
- **注意**：这是唯一会在学校服务器留下可审计痕迹的地方；建议填真实的校区和教室，不要填明显不实的内容
- 本工具只做"签到"这一件事，不修改任何课程数据

## 七、目录与文件

```
auto-checkin\
├─ 打开控制台.lnk          ← 零黑框入口（推荐）
├─ run-dashboard.cmd       ← 源码模式打开控制台（调试用）
├─ start-watchdog.cmd      ← 启动看护进程（建议双击一次）
├─ run-/stop-/status-autowatch.cmd
├─ stop-dashboard.cmd
├─ check-records.cmd       ← 只读自检：token / 网络 / 接口
├─ build-exe.cmd           ← 重新打包程序
├─ build-setup.cmd         ← 重新打包 + 生成安装包
├─ data\                   ← 配置（课表 / 设置 / 凭据 / token）
├─ logs\                   ← 日志（autowatch / watchdog / cli / session-result…）
├─ output\                 ← 截图（实时画面、抓到的二维码）
└─ app\                    ← 程序本体
```

出问题时最有用的三个文件：

- `logs\autowatch.log` —— 每节课在干什么
- `logs\session-result.json` —— 上一节的结论
- `logs\cli.log` —— 打包版程序的输出（没有控制台时都写这里）

## 八、卸载

开始菜单 → 自动签到 → 卸载（或控制面板卸载）。

数据目录 `%APPDATA%\auto-checkin\` 会保留，要彻底清掉请手动删除。
